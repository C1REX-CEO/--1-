# Лаба 3: последовательная программа и MPI на «Сергее Королёве»

## 1. Подключение

Сначала войдите в университетскую сеть через настроенный Ideco Client.
Адрес VPN нужно взять из инструкции университета/профиля клиента. Домен
кабинета — `vpn.ssau.ru`, а `ike.vpn.ssau.ru` в ранее выданном PowerShell-скрипте
относился к IKEv2-подключению средствами Windows. Эти параметры не следует
механически смешивать. При необходимости подтвердите адрес Ideco Client
в кабинете или у преподавателя.

Затем в WinSCP создайте подключение:

| Поле | Значение |
|---|---|
| Протокол | SFTP |
| Имя хоста | `sk.ssau.ru` |
| Порт | `22` |
| Пользователь | Выданный SSH-логин суперкомпьютера |
| Пароль | Пароль этой учётной записи, вводится в окне WinSCP |

При первом входе сверяйте отпечаток SSH-ключа с данными администратора.
GitHub-аккаунт не является учётной записью кластера. VPN и учётная запись
кластера — отдельные условия доступа.
Официальная инструкция: https://hpc.ssau.ru/node/20 .

## 2. Что загружать

Архив `lab3-korolev-upload.zip` содержит только исходники и скрипты третьей лабы.
Распакуйте его на своём компьютере и через WinSCP загрузите папку `lab3-upload`
в свою домашнюю директорию на кластере. Сохраните структуру папок.

Две программы:

- `lab3_mpi/serial.cpp` → `matrix_serial`, обычное последовательное умножение;
- `lab3_mpi/main.cpp` → `matrix_mpi`, распределение строк между MPI-процессами.

Готовые Windows `.exe` на Linux-кластер не загружаются. Сборка производится
на кластере скриптом `lab3_mpi/build_linux.sh`, который вызывается из PBS-задания.
Обе программы используют C++17, `-O2`, одинаковое целочисленное умножение `i-k-j`
и один формат файлов: N, затем N строк по N чисел.

## 3. Окружение и отправка задания

В терминале SSH:

```bash
ssh LOGIN@sk.ssau.ru
cd ~/lab3-upload
module avail
qstat -q
```

Нужны C++17, согласованные компилятор и MPI, Python 3.10+ с NumPy/matplotlib.
Список модулей на сайте старый: подтвердите доступные версии на самом кластере.
`impi/4` в `job.pbs` взят из официального примера и может потребовать замены.
Наш адаптер `korolev_mpirun.sh` использует Intel MPI; при выборе Open MPI
команду запуска потребуется адаптировать.

После проверки модулей и получения кода проекта:

```bash
qsub -A PROJECT_CODE lab3_mpi/job.pbs
```

Если нужны другие модули/пути:

```bash
qsub -A PROJECT_CODE \
  -v COMPILER_MODULE=ACTUAL_COMPILER,MPI_MODULE=ACTUAL_INTEL_MPI,PYTHON=/path/to/python3,CXX=g++,MPICXX=mpicxx \
  lab3_mpi/job.pbs
```

LOGIN, PROJECT_CODE, ACTUAL_COMPILER, ACTUAL_INTEL_MPI и /path/to/python3
заменяются реальными значениями. Скрипты не знают их заранее.

PBS-задание запрашивает **1 узел, 8 ядер и 1 час**. Последовательно выполняются:

1. Сборка и проверки обеих программ.
2. Последовательная версия: N=200,400,800,1200,1600,2000, по три повтора.
3. MPI-версия: те же размеры, p=1,2,4,8, по три повтора.
4. Для каждого запуска — сравнение всей результирующей матрицы с NumPy.
5. Расчёт медиан, ускорения, эффективности и графиков.

Всего 18 последовательных и 72 MPI-замера. Выделение остаётся 8 ядер;
внутри него меняется число работающих процессов. Реальное закрепление процессов
за физическими ядрами нужно проверить в выбранной MPI-среде и описать в отчёте.
На головном узле эксперименты не запускаются.

Контроль очереди:

```bash
qstat -a
qstat -f JOB_ID
```

Инструкции: https://hpc.ssau.ru/node/21 и https://hpc.ssau.ru/node/36 .

## 4. Результаты и отчёт

После завершения скачайте через WinSCP папку
`lab3_mpi/results_korolev/JOB_ID/` и stdout/stderr PBS-задания.
Для отчёта нужны:

- `serial/raw.csv` — все 18 последовательных измерений;
- `raw.csv` — все 72 MPI-измерения, p, N и статус проверки;
- `summary.csv`, `tables.md` — медианы, min–max, ускорение и эффективность;
- `speedup_serial.png` и `efficiency_serial.png` — сравнение с отдельной последовательной программой;
- `checks_serial.json`, `checks.json` — проверки обеих версий;
- `environment.json`, `serial/environment.json`, `cluster_environment.txt`,
  `pbs_nodefile.txt`, `pbs_job.txt`, `build.log` — подтверждение окружения и запуска.

В MPI-время включены рассылка B, распределение A, вычисление и сбор C.
В serial-время входит умножение. Файловый ввод/вывод и проверка исключены.
`speedup_serial = Tserial/Tmpi`, `efficiency_serial = speedup_serial/p`.
Поля `speedup` и `efficiency` отдельно показывают масштабирование относительно
**MPI на одном процессе**. Два вида базовой линии нельзя путать.

Обе версии получают одинаковые матрицы (целые −10…10, seed `42+N`).
Точный NumPy-эталон вычисляется через float64 BLAS: все промежуточные целые
суммы значительно меньше 2^53, поэтому здесь нет ошибки округления.
Малые тесты дополнительно используют прямое целочисленное NumPy-умножение.

Финальный отчёт составляется по фактическим кластерным данным: задание,
описание двух алгоритмов, исходный код, оборудование/ПО, методика,
результаты, графики и выводы. Пока кластерное задание не выполнено,
лабораторная №3 остаётся незавершённой.
