# Запуск на «Сергее Королёве»

> **Обновление 11.11.2026:** фактическое окружение использует Slurm.
> Актуальный запуск описан в [SLURM.md](SLURM.md).
> PBS/TORQUE-команды ниже сохранены для истории и не подходят к текущему серверу.

Подготовлено по официальным инструкциям СКЦ Самарского университета,
проверенным 6 ноября 2026. Файлы задания проверены локально; реального
запуска на кластере пока не было.

## 1. Доступ

Головной узел — `sk.ssau.ru`. Вход по SSH разрешён из корпоративной сети
университета или с IP, указанного при регистрации. Файлы передаются SCP/SFTP:
[инструкция СКЦ](https://hpc.ssau.ru/node/20).

Для доступа к корпоративной сети пользователь указал
[VPN-кабинет университета](https://vpn.ssau.ru/cabinet/#/login).
Авторизоваться и настроить VPN нужно по инструкции в кабинете.
Публичная [FAQ университета](https://help.ssau.ru/otrs/public.pl?Action=PublicFAQPrint&ItemID=40)
ссылается на документацию Ideco. Конкретный способ подключения и учётная запись
определяются кабинетом; наличие OpenVPN и совпадение пароля с SSAU_id не предполагаются.

VPN даёт сетевую доступность, но для суперкомпьютера дополнительно требуются:

- учётная запись и SSH-логин кластера;
- код проекта для `qsub -A`;
- разрешение на использование ресурсов этого проекта.

Если этих данных нет, их нужно получить у преподавателя/администрации по
[процедуре регистрации](https://hpc.ssau.ru/node/15).
Задачи привязываются к проекту согласно
[правилам распределения ресурсов](https://hpc.ssau.ru/node/565).
Пароли, закрытые ключи и персональные VPN-конфигурации в репозиторий не добавляются.

## 2. Проверка программного окружения

После подключения (заменить `LOGIN` своим SSH-логином):

```bash
ssh LOGIN@sk.ssau.ru
module avail
qstat -q
```

В [официальном примере MPI](https://hpc.ssau.ru/node/36) указан модуль `impi/4`
и команды `mpicxx`, `mpirun`. Опубликованный [список ПО](https://hpc.ssau.ru/node/12)
содержит старые версии, поэтому актуальные модули нужно проверить на самом кластере.
Для этой реализации необходимы C++17, Python 3.10+ и NumPy/matplotlib.
Не следует считать, что компилятор по умолчанию или системный Python подходят.
Подходящие модули/готовое Python-окружение выбираются по фактическому выводу
и рекомендациям администратора. Само задание проверяет зависимости до экспериментов.

## 3. Файл задания

Планировщик — TORQUE/Moab, формат PBS. MPI запускается только через очередь;
прямой вход на вычислительные узлы запрещён.
[Правила запуска и qsub](https://hpc.ssau.ru/node/21).

[job.pbs](job.pbs) запрашивает один узел и восемь ядер на один час. Внутри
**одного** задания последовательно выполняются конфигурации p=1,2,4,8,
по шести размерам и с тремя повторениями. Выделение остаётся равным восьми ядрам,
а число работающих MPI-процессов меняется; это фиксируется в отчёте.

Адаптер [korolev_mpirun.sh](korolev_mpirun.sh) использует Intel MPI-синтаксис
из документации СКЦ и выделенный `PBS_NODEFILE`. Он отклоняет запуск вне PBS
и запрос числа процессов больше выделенного. При смене MPI-реализации
нужно согласованно заменить модуль и адаптер, а не смешивать Open MPI и Intel MPI.
Закрепление процессов за ядрами и версии MPI следует проверить в настоящей
сессии; опубликованные примеры не доказывают фактическую CPU affinity.

Из корня загруженного репозитория:

```bash
# PROJECT_CODE заменить выданным кодом проекта.
qsub -A PROJECT_CODE lab3_mpi/job.pbs
qstat -a
qstat -f JOB_ID
```

При необходимости передать подтверждённые на кластере настройки:

```bash
qsub -A PROJECT_CODE \
  -v COMPILER_MODULE=ACTUAL_COMPILER,MPI_MODULE=ACTUAL_INTEL_MPI,PYTHON=/path/to/python3 \
  lab3_mpi/job.pbs
```

Значения с `ACTUAL_` и `/path/to/` — места для реальных параметров,
не готовые имена модулей. Если модуль использует другой C++ wrapper,
можно дополнительно передать `MPICXX`.
Скрипт не устанавливает пакеты и не отправляет письма.

## 4. Сохранение результатов

Каждое задание создаёт отдельную папку `lab3_mpi/results_korolev/JOB_ID/`:

- `raw.csv` (72 MPI-замера), `serial/raw.csv` (18 последовательных), `summary.csv`, `tables.md` и графики;
- `checks.json`, `checks_serial.json` и stdout каждого запуска;
- `environment.json`, `cluster_environment.txt`, `pbs_nodefile.txt`, `pbs_job.txt`;
- `build.log`, два бинарных файла и временные матрицы.

Перед MPI-серией тот же PBS-скрипт выполняет отдельную последовательную
программу. В `summary.csv` поля `speedup_serial`/`efficiency_serial` сравнивают
MPI с ней; `speedup`/`efficiency` сохраняют сравнение с MPI на одном процессе.
Пошаговая инструкция и содержимое архива для WinSCP — [START_HERE.md](START_HERE.md).

Бинарный файл и временные данные исключены из Git. Существующий `raw.csv`
защищён от повторной перезаписи скриптом. Локальная проверка в `lab3_mpi/checks.json`
сохраняется отдельно. После успешного выполнения нужно перенести результаты,
дополнить [отчёт](README.md) сведениями о выделенных ресурсах и выводами, затем
снять пометку о незавершённом суперкомпьютерном этапе.
